## Dedupe, usage and missing measurements

Across eight questions: 1,403 returned clusters, nine date exclusions, 33 logical
HTTP attempts (including retries), 32 search-page calls and zero host tool calls.
Captured wall clock totals 42,078 ms (mean 5,259.75 ms per question).

Dedupe counts are observed pair counts: true / false / missed merges = 0 / 0 / 0;
**19 unjudged merge pairs mean these zeros do not establish perfect dedupe**.
The JSON also includes per-domain aggregates.

Replay `wall_clock_ms` is captured timing, not the speed of this implementation
on today's machine; it cannot establish a code-speed improvement. Logical HTTP
attempts are not live requests: replay network traffic is zero. Engine token
usage and billed USD are null, not a measured zero cost. Citation correctness is
null with `citation_status: not_implemented` in every row. This run does not
measure claim-to-passage correctness, semantic support or human approval.

## Reproduce exact bytes

From the repository root with Go 1.26.6 and engine sources at the measured revision
(or this docs-only publication), run:

```sh
set -eu
revision=8583b34f5859ed9cf49fdb49d3b3c9024174e573
git diff --exit-code "$revision" -- cmd internal go.mod go.sum
work=$(mktemp -d "${TMPDIR:?}/rforge-baseline.XXXXXX")
go build -ldflags "-X main.version=dev -X main.commit=$revision" \
  -o "$work/rforge" ./cmd/rforge
"$work/rforge" benchmark run --replay --set benchmarks/sets/pool-a \
  --split held_out --out "$work/report.json"
"$work/rforge" benchmark run --replay --set benchmarks/sets/pool-a \
  --split held_out --out "$work/replay.json"
cmp "$work/report.json" "$work/replay.json"
cmp docs/benchmark/baseline-2026-10-19.json "$work/report.json"
sha256sum "$work/report.json"
```

Set `TMPDIR` to a scratch directory first if unset. Both comparisons must exit
zero and the SHA-256 must match the file hash above. Reports use canonical JSON
plus a final LF. Explicit linker values preserve engine identity; plain `go run`
uses revision `unknown`. For future comparisons build the new engine with its
own version/revision, never this baseline's identity. Keep generated
`*.audit.json` sidecars private in scratch space: raw records and cluster
membership are scorer-only, not baseline publication artifacts.

## Limits and future comparisons

This small, clinically skewed convenience pool does not establish that rforge
improves an agent's research or satisfies the 2.0 release gate. Artificial
photosynthesis is absent under the locked `ap_domain_absent` owner waiver. The
[review sheet](../../benchmarks/sets/pool-a/review.md) documents source/date
uncertainties and the pending independent source audit of 99 of 113 set-wide gold
records (V-B4-LIVE). Replay does not resolve that audit or change set approval.
Modern captures reflect retrospective indexing and metadata, not historical
databases. Precision is **gold-set precision**: non-gold papers may still be
scientifically relevant.

Improvement claims must cite this baseline and JSON with signed deltas (new minus
baseline), metric/K and macro/micro aggregation, both engine versions/revisions,
set checksums, snapshot digests and protocol hashes. Implementation comparisons
must use identical locked inputs; changed inputs require a newly approved set
and baseline, not an implementation-win claim. Unavailable metrics stay null.

Tune on `dev`, never these held-out outcomes. If detailed held-out results guide
a change, mark this set version exposed and obtain a newly approved held-out set
for fresh improvement claims, per the [leakage controls](spec.md#3-leakage-controls-and-access-separation).
Preserve this dated baseline rather than overwriting it. Revisit comparisons
when connectors, normalization, dedupe, scoring, citation metrics or the protocol
change, disclosing any protocol/metric incompatibility.
