## Chosen batch and alternatives

**Planner call:** add one standalone offline engine-report comparison utility and one test-only public-pilot readback lane. The utility is external benchmark tooling at `benchmarks/report-delta`, not a new `rforge` command or adapter feature. Reuse internal aggregation/strict decoding; do not fork the scorer. The readback lane turns demonstrated temporary checks into maintainable offline guards without touching the live adapter.

Manual deltas alone were rejected because they leave the accepted comparison rules unenforced. Extending the live gateway was rejected because it overlaps the explicitly deferred V0-012. Wiring new citation inputs into the historical registration was rejected because it changes its measured protocol and requires evidence the published package does not contain.

### Outcome A — compatible engine-report deltas

Create `internal/benchmarks/comparison.go` and `comparison_test.go`, plus `benchmarks/report-delta/main.go`, `main_test.go` and `README.md`. Provide `CompareEngineReports(baseline, candidate EngineReport) (EngineComparison, error)` and a stdlib-only command:

```text
go run ./benchmarks/report-delta --baseline OLD.json --candidate NEW.json
```

The command reads existing files only, prints canonical JSON plus LF to stdout, errors to stderr and exits nonzero on rejection. No output-file/overwrite mode or input modification is needed. Output contains both reports' version/revision, set ID/checksum, snapshot digest, protocol digest, split and K; sorted aggregate rows keyed by condition/domain/metric/K; both contributing question counts; and baseline/candidate/delta values separately for macro and micro (micro absent for non-ratio metrics). Delta is always candidate minus baseline; if either measurement is unavailable its delta is null, never zero. Include explicit limitations: replay latency is captured timing, reports alone do not prove input custody, and differences are not a release/superiority verdict.

Accept only complete, error-free schema-v1 engine **replay** reports with matching purpose, set ID/checksum, non-null snapshot digest, protocol digest, split, K and question/domain/gold-count matrix. Versions/revisions may differ and must remain visible. Reject agent/record/demo reports, malformed or duplicate JSON fields, missing/duplicate question or aggregate keys, inconsistent ratios/counts and supplied aggregates that disagree with recomputation from rows. Reuse `aggregate` rather than adding another scoring formula. Where both sides have measured aggregate values, require the same contributing questions; otherwise reject that comparison rather than subtract unlike populations. Availability may differ, but then the affected delta is null. Comparison validates internal consistency/compatibility, not a signature or actual set approval.

Proposed tests: `TestEngineReportComparison` (hand-calculated signed macro/micro deltas, domain/K separation, nulls, self-comparison), `TestEngineReportComparisonRejectsIncompatibleInputs` (table of compatibility and internal-consistency failures), and `TestReportDeltaCommand` (strict input decoding, deterministic stdout, errors, unchanged files; read the dated baseline as immutable input). Build synthetic reports from `fixture-tiny`/in-memory data, not by tuning pool-a outcomes. Required checks are these focused packages and the normal full check.

### Outcome B — public pilot readback regression guards

Create `benchmarks/agent-tier/pilot_readback_test.go` and, if useful, `pilot_readback_helpers_test.go`; document the check and its limits in `benchmarks/agent-tier/README.md`. Keep all helpers test-local. Read the existing `pilot-pi-2026-10-21/` package and locked set as immutable inputs; score to `t.TempDir()` using existing `scoreAnswers` and compare scores/freeze bytes. Recompute aggregates and all paired contrasts from published report rows using existing summaries; compare floats with a documented tolerance (planner default absolute `1e-9`), integers/digests/nulls exactly. Recompute analysis recall differences, sample SD, paired effect and the registered normal-approximation sizing from the published rows and analysis parameters.

Validate the 8 × 2 × 3 unique row matrix against protocol/schedule, public protocol/answers/scores/report canonical digest links, and honest unavailable facets. Preserve all provider-loss flags, the 24 failed native observations/48 failed native attempts, and 23 with-tools budget stops rather than silently dropping rows. Use public provider events and counters to reconcile availability, not private transcript/billing assertions. The registration and protocol may be read but never changed. No private mapping is available: this check cannot rejoin original condition assignments, certify historical blindness, verify billed identities or reproduce the custodian's private execution audit.

Proposed tests: `TestPublishedPilotReadback` checks the real committed package without writes; `TestPublishedPilotReadbackRejectsTampering` passes temporary copies with one missing/duplicate slot, changed digest, contrast, availability flag or null facet to a test-local validator and requires rejection. The latter provides a red/green seam for missing guards; deliberate mutations never touch original files. No Pi installation, model, network or bubblewrap dependency is needed; this is an artifact regression check, not OS-isolation qualification.
