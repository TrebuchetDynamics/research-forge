## Sources and observed defect

- Sources: docs/cli.md (Persistent research jobs and MCP lifetime contract); docs/verifiable-engine-plan.md#verifiable-research-engine-plan (thin MCP adapter over shared services); internal/sources/transport/http.go::NewHTTPClient/do/wait; internal/cli/source_commands.go::defaultSourceHTTPClient/defaultSemanticScholarHTTPClient; internal/cli/mcp_command.go::executeMCP; internal/mcp/server.go::Serve.
- Evidence at a5796b807d76aa46ab2bbf29134ba183a019c868: NewHTTPClient defaults Sleep to time.Sleep; wait checks ctx.Err only before/after c.sleep(d). The same wait handles RequestDelay and Retry-After. Normal clients provide neither Wait nor Sleep; Semantic Scholar permits up to 120s Retry-After by default. Serve cancels then workers.Wait on disconnect, so cancellation during a sleep delays checkpointing/exit until that sleep ends. This is source-proven control flow, not a live incident claim.
- Coverage gap: internal/sources/transport/http_test.go pins retry durations using injected Sleep and HTTP timeout behavior, but has no cancellation-during-wait test. internal/mcp/lifecycle_test.go covers cancellation while RoundTrip is blocked, not backoff. Preserve those existing tests; add TestSearchDisconnectDuringRetryWait in the new integration file.
