## Discovery evidence and readiness

- Baseline: internal/webui/webui.go:356 and :364 render the create/open forms as `<form hx-post="/projects/create" hx-target="#project-status">` and `<form hx-post="/projects/open" hx-target="#project-status">`; internal/webui/server.go:207 renders the switch form as `<form hx-post="/projects/switch" hx-target="#active-project-path" hx-swap="outerHTML">`. None carries method or action, so a JavaScript-disabled browser performs the HTML default same-page GET and never reaches NewCreateProjectHandler, NewOpenProjectHandler or newSwitchProjectHandler, all of which already accept POST and render usable fragments. The sibling source-planning form at internal/webui/webui.go:84 already uses native `method="get" action="/sources"` and is covered by TestSourcePlanningFormRoundTrip, so the repair has an in-tree precedent.
- User benefit: a user with JavaScript disabled (or when the vendored htmx asset fails to load) can create, open and switch a local research folder and see the resulting status instead of the form silently resetting. The change is progressive enhancement only: with htmx present the existing hx-post path and rejection feedback are unchanged.
